# Регламент и Q&A: суть для разработки

## Сабмит
- `solution.py` читает из `DATA_DIR` (по умолчанию `data`) файлы `questions.csv` (`id,question`) и `knowledge-base.zip`. Результат пишет в `submission.csv` (`id,answer`, UTF-8, CSV-экранирование). На каждый id — один непустой ответ.
- История диалога приходит в тексте вопроса: «Пользователь: … / Ассистент: … / Пользователь: …». Отвечаем на последнюю реплику. Между id ничего не сохраняется.
- Ссылки на пункты и статьи пишем прямо в ответе. Ответ — до 150 слов (максимум 10 000 символов).
- ZIP: всё в корне, без вложенных папок — `solution.py`, `requirements.txt`, наши `.py`-модули, готовый индекс.
- Библиотеки — только из выданного `requirements.txt`. torch и sentence-transformers там нет. `pip install` из кода запрещён.

## Лимиты
- 5 сабмитов в день (сброс в 00:00 МСК), ZIP до 128 МБ, 8 CPU и 16 ГБ RAM без GPU.
- **20 минут на весь прогон.** На ошибки 429 и 5xx — ограниченные ретраи с паузой.

## Модели и env
- На платформе работает прокси, OpenAI-совместимый: `/chat/completions` (DeepSeek V4.1 Flash), `/embeddings` (bge-m3), `/rerank` (Qwen3 Reranker 8B).
- **Всё берём из env, ничего не хардкодим:** `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `EMB_MODEL`, `RERANKER_MODEL`, `TEMPERATURE`, `MAX_TOKENS`, `MAX_WORKERS`, `DATA_DIR`.
- **Ключей для локальной разработки не дают.** Локально работаем через замену: DeepSeek API со своим ключом и bge-m3 локально, с тем же интерфейсом. Реальная модель доступна только в сабмитах.
- Жюри при локальном запуске через Docker передаёт API сами. Веб и `solution.py` читают одни и те же переменные.

## Оценка
- LLM-судья сравнивает наш ответ с бейзлайном, ориентируясь на эталон. Итог: 70% Match Rate (средний балл) + 30% Win Rate (доля побед над бейзлайном).
- **Выдуманный факт обнуляет оценку за вопрос.**
- Во время хакатона лидерборд считается на public-вопросах, итог — на private. **База знаний одна и та же**, отличаются только вопросы.

## Поведение бота (Q&A)
| Ситуация | Реакция |
|---|---|
| Ответ есть в базе | Ответ со ссылками на пункты и статьи |
| Данных хватает частично | **Частичный ответ** + чего не хватает (лучше полного отказа) |
| Ничего релевантного в базе | Отказ: в базе нет, по памяти не отвечаю |
| Не юридический вопрос | Полный отказ |
| Незаконный запрос | Отказ (разъяснить требования и последствия по базе можно) |
| Ошибка в вопросе | Поправить пользователя со ссылкой |
| Нужна редакция на дату | Применить редакцию на дату события с учётом допсоглашений |

Главное — **не фантазировать**.

## База знаний
- 21 TXT-файл: 13 статей законов (только действующие редакции) и 8 документов ООО «Меридиан» — договоры, допсоглашение, регламент в редакциях 2023 и 2025, служебная записка, письмо.
- Предобрабатывать можно как угодно, организаторы намекнули, что это ключ к хорошему решению. **Дополнять базу нельзя.**
- Ловушки:
  - контрагенты «Альфа-Трейд» (П-17/2024) и «Альфа-Трейдинг» (ПТ-05/2023);
  - регламент действует в двух редакциях;
  - допсоглашение меняет пункт договора;
  - НК ст. 164 и 284 огромные, по ~150 тыс. символов.

## Решения по архитектуре
1. Базу обрабатываем заранее: структура, карточки документов, связи, синонимы. Эмбеддинги считаем локально bge-m3, готовый индекс кладём в корень ZIP.
2. Один вызов LLM на вопрос — так укладываемся в 20 минут.
3. Общий `config.py` для `solution.py` и веба.
4. Сабмиты экономим: в каждом одно изменение, результат записываем.
